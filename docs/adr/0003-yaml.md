# 0003. YAML: `go.yaml.in/yaml/v3`

- Status: Accepted
- Date: 2026-10-28
- Deciders: Florian (via J0 plan T4)

## Context
`config.yaml` (spec, Configuration) is the only config file. T13 requires strict decoding:
an unknown or misspelled key must be a configuration error (exit 2), never silently
ignored, because a typo in a `secrets` or `state_dir` field would weaken security. We need
`Decoder.KnownFields(true)`, decoding into typed structs, and line numbers in errors.
The spec table names `gopkg.in/yaml.v3`, which is no longer maintained.

## Decision
`go.yaml.in/yaml/v3` **v3.0.5** (2026-07-26): the continuation of go-yaml v3 maintained
by the YAML organization after the original author marked `go-yaml/yaml` unmaintained in
April 2025 (per its README). Same API as `gopkg.in/yaml.v3`, including
`(*Decoder).KnownFields`. Only `internal/config` imports it. No other module is added to
the build (`go list -deps` shows only itself).

pdfcpu (ADR 0006) already requires `go.yaml.in/yaml/v3` v3.0.5, so this choice adds no
extra YAML library to the binary.

## Alternatives
| Option | Why not |
| --- | --- |
| `gopkg.in/yaml.v3` v3.0.1 (2022-05-27) | Archived upstream, no fixes since 2022 |
| `go.yaml.in/yaml/v4` (v4.0.0-rc.6, 2026-06-17) | Release candidate only; revisit at v4.0.0 |
| `github.com/goccy/go-yaml` v1.19.2 (2026-01-08, MIT) | Good and maintained, but a second YAML stack next to pdfcpu's |
| `sigs.k8s.io/yaml` v1.6.0 | YAML → JSON wrapper; loses YAML line info for errors |
| `github.com/knadh/koanf/v2` (spec alternative) | Layered config is not needed; adds providers/parsers |
| JSON or TOML | Spec fixes YAML for user-edited config |

## Maintenance
Versions: v3.0.2 and v3.0.3 (2025-06-02), v3.0.4 (2025-06-29), v3.0.5 (2026-07-26).
Low cadence by design (stable v3 line); active development happens on v4. Maintained by
the YAML organization with downstream representatives (README); individual names unverified.

## Consequences
- Strict decoding for every config load; tests `TestLoad_RejectsUnknownFields`.
- Revisit when v4 is final or if v3 receives no security fix within a reasonable delay.
