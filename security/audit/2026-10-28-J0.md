## Open findings

### SEC-J0-11 (high, cat 8): reachable Go stdlib vulnerabilities, toolchain go1.27.1
- **Location:** `go.mod:3` (`go 1.27.1`). CI and release take the toolchain from it
  (`go-version-file: go.mod`, `.github/workflows/release.yml:16`), so a release
  would ship the vulnerable stdlib.
- **Evidence:** govulncheck reports:
  - GO-2026-6809: distrust compromised intermediates in crypto/x509. Fixed in go1.27.3.
  - GO-2026-6610: HTTP/2 transport accepts malformed headers.
  - GO-2026-6605: HTTP/1 client desync after a rejected CONNECT.
  - GO-2026-6607: crypto/tls ECH.
  - GO-2026-6608: net/textproto memory-limit bypass.
  - GO-2026-6603, 6611, 6613 and 6617: net/http.
  - GO-2026-6604: os.Root junctions, Windows only, which affects `internal/fsx` confinement on Windows.

  Traces go through `internal/httpx/httpx.go:249` (`guard.RoundTrip` → `http.Transport.RoundTrip`)
  and `internal/normalize/facturx/parse.go:145`. GO-2026-6809 weakens the TLS trust
  that the httpx allowlist relies on.
- **Why high:** the scanner gate is 0, the code is reachable from production
  packages, and it affects certificate trust and the Windows fsx root. Runtime
  exposure at J0 is limited (no connector ships), but the release artifact would carry it.
- **Fix:** set `go 1.27.3` (or `toolchain go1.27.3`) in `go.mod`, install it locally,
  and re-run `make audit`.
- **Regression:** the govulncheck gate in `make audit` and the weekly `security.yml` run.

### SEC-J0-13 (medium, cat 8): release pipeline has no goreleaser config

- **Fix:** add `.goreleaser.yaml` with:

  - `ldflags -X main.version`
  - `sboms:` (syft)
  - `signs:` (cosign keyless, checksum file)

  Add a `make release-check` (`goreleaser check`) to CI.

### SEC-J0-15 (medium, cat 5): "httpx only" is not lint-enforced repo-wide
- **Location:** `.golangci.yml:28` forbids only `http.(Get|Post|Head|DefaultClient)`.
  `.golangci.yml:44` exempts `cmd/` from forbidigo entirely.
- **Evidence:** nothing forbids importing `net`, `net/http` or `crypto/tls`,
  building an `http.Client{}`, using `http.DefaultTransport` or `net.Dial` outside
  `internal/httpx`. The only import guard is `internal/orchestrator/imports_test.go`,
  which covers that one package. A J1 connector under `connectors/` could open a raw
  connection without any lint or test failing. No such code exists today: production
  `net/http` imports are only in `internal/httpx/*` and `internal/logx/walk.go`
  (type detection).
- **Fix:** add a depguard rule denying `net`, `net/http`, `net/http/**` and
  `crypto/tls` for all files except `internal/httpx/**`, with a narrow allow for
  `internal/logx/walk.go`. Alternatively, add a repo-wide import test like
  `imports_test.go` that walks every package (including `connectors/`).

### SEC-J0-16 (low, cat 6): "fsx only" lint has gaps
- **Location:** `.golangci.yml:30` forbids `os.(WriteFile|Create|OpenFile|MkdirAll)` only.
  `.golangci.yml:44` exempts `cmd/`.
- **Evidence:** these calls are not caught: `os.Mkdir`, `os.Rename`, `os.Remove`,
  `os.RemoveAll`, `os.Symlink`, `os.Link`, `os.Chmod`, `os.CreateTemp` and `os.MkdirTemp`.
  A repo grep finds none of them in production code today, so this is a guard gap,
  not a violation.
- **Fix:** extend the pattern list. Narrow the `cmd/` exclusion to the patterns
  `cmd/` actually needs. `cmd/facto` writes only through `fsx` today, so it needs none of the fs ones.

### SEC-J0-17 (low, cat 6): synced-folder detection ignores symlinks
- **Location:** `internal/config/paths.go:67` (`syncedFolder`, lexical). The resolved
  path from `cmd/facto/statedir.go:34` (`resolveMissing`) is used only for the
  output-folder check.
- **Evidence:** `state_dir: ~/state` where `~/state` is a symlink into
  `~/Dropbox/x` gets through both checks. This is documented in `docs/security.md`
  ("State dir sync detection is name-based").
- **Fix:** in `checkStateDirOutside`, also run `config`'s synced-name test on the
  resolved path (`realState`). Add a unit test with a symlink into a `Dropbox` folder.

### SEC-J0-18 (low, cat 6): owner-only permission checks are no-ops on Windows
- **Location:** `internal/fsx/perm_windows.go`, `internal/config/perm_windows.go`.
- **Evidence:** Go reports synthetic POSIX modes on Windows. Documented as a known
  limitation, with an ACL check planned for J1.
- **Fix:** an owner-only DACL check (x/sys/windows) with an ADR, in J1.

### SEC-J0-19 (low, cat 4): CLI error output bypasses the redacting cleaner
- **Location:** `cmd/facto/main.go:111`: `fmt.Fprintf(stderr, "facto: %v\n", err)`.
  `cmd/facto/collect.go:131` prints `runErr` through it.
- **Evidence:** run-level errors (index, output folder, inbox scan) reach stderr as
  raw `err.Error()`, without `logx.Clean`. `internal/inbox/scan.go:163` quotes the
  inbox name with `%q`, but the wrapped `*os.PathError` repeats the same untrusted
  name unquoted. A file name with ESC or bidi sequences can then reach the terminal
  when an I/O error hits it.
  Severity is low: it needs a hostile file name in `inbox/` plus an I/O error, and no secret is involved.
- **Fix:** have `writeErr` print `logx.Clean(err.Error())`, which strips control
  characters and applies pattern masking. Add a CLI test with an ESC-named inbox
  entry made unreadable.

### SEC-J0-20 (low, cat 4): lexical free-text masking gaps
- **Location:** `internal/logx/kv.go` (free-text `key=value` masking).
- **Evidence:** documented in `docs/security.md` "Known limitations":
  - multi-word unquoted values (`password: correct horse battery` keeps `horse battery`)
  - key and value split across lines
  - XML elements (`<password>`)
  - `=>` and `->` separators
  - the URL edge case `@` … `/` … `#` in `net/url` parse errors

  Structured attributes are not affected.
- **Fix:** accept formally (Florian), or mask to end of line after a sensitive key
  followed by `:`, as is already done for header lines.

### SEC-J0-21 (low, cat 1): password-manager subprocess environment readable by same uid
- **Location:** `internal/secret/bitwarden/exec.go:41` (`c.Env = env`) and
  `internal/secret/bitwarden/bitwarden.go:244` (master password in `FACTO_BW_MASTER_PASSWORD`).
- **Evidence:** `/proc/<pid>/environ` of the CLI child is readable by the same uid
  (PTRACE_MODE_READ, not restricted by Yama scope 1). `PR_SET_DUMPABLE=0` on facto
  does not carry to the child. The threat model lists "another program on the same
  machine". The design follows the rubric (`--passwordenv`), so this is low and documented.
- **Fix:** for unlock, give the password through `--passwordfile /dev/fd/3` backed by an
  `os.Pipe` in `ExtraFiles` (nothing in environ or on disk). This needs an ADR, since
  `--passwordfile` is currently on the never-used list. Session-key exposure in the
  child environment is inherent to the CLI; accept and document.

### SEC-J0-22 (low, cat 1): secret providers not wired; lock-on-exit unproven end to end
- **Location:** `cmd/facto/collect.go:101` (`collect` never builds a `secret.Resolver`).
- **Evidence:** `cmd/facto/*.go` imports neither `internal/secret` nor its providers.
  The provider locks on `Close` and on fatal errors (`TestBitwarden_LocksOnCloseAndError`),
  but no production call site has `defer resolver.CloseAll()`. `make e2e` starts
  Vaultwarden but no scenario uses it. This is documented ("The secret resolver is
  not wired into collection").
- **Fix (J1):** wire the resolver with `defer CloseAll()` in `collect`. Add an E2E
  scenario against Vaultwarden asserting the vault is locked after success, error
  and SIGINT, with canaries in leakcheck.

### SEC-J0-23 (low, cat 7): keyring lookup has no timeout and blocks the resolver
- **Location:** `internal/secret/keyring/keyring.go:54` (`p.backend.Get(...)`, `ctx` not honoured)
  and `internal/secret/resolver.go:98` (RLock held during the provider call).
- **Evidence:** go-keyring's Secret Service call (D-Bus) cannot be cancelled. A hung
  keyring daemon blocks `Resolve` forever. `CloseAll` needs the write lock, so it
  blocks too, and the password-manager lock never runs while the process lives.
- **Fix:** run `Get` in a goroutine and `select` on `ctx.Done()` and a bounded
  timeout. Return `ctx.Err()` and let the goroutine finish. Add a test with a blocking fake backend.

### SEC-J0-24 (low, cat 7): new J0 parsers lack fuzz tests
- **Location:** `internal/secret/ref.go:51` (`ParseRef`), `internal/config/load.go:80`
  (`Parse`), `internal/logx/kv.go` (free-text scanner over hostile text).
- **Evidence:** fuzz targets exist only for facturx (`FuzzParseCII`, `FuzzExtract`),
  normalize (`FuzzRender_StaysInsideDir`, `FuzzSlug`) and fsx
  (`FuzzSafeName_NeverContainsSeparatorOrDotDot`).
- **Fix:** add these fuzz targets:
  - `FuzzParseRef`: canonical round trip; the error never contains the input.
  - `FuzzParse`: no panic; the error never contains a scalar from the input.
  - `FuzzClean`: an embedded canary after a sensitive key never survives; bounded time.
